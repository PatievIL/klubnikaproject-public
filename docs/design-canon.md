# Klubnika Project Design Canon

## Core Definition

Klubnika Project is a practical farm system interface, not a promotional landing style.

The site should feel calm, technical, warm, and useful. It helps a visitor decide what to do next: calculate a farm, open the catalog, study the base, request consultation, or leave an application.

## Visual Base

- Background: warm beige, not white.
- Primary color: deep green.
- Surfaces: cream panels and cards.
- Borders: thin green-tinted lines.
- Shadows: minimal, soft, only when they clarify hierarchy.
- Corners: moderate radius, usually 14-28px depending on scale.
- Gradients: restrained green gradients are allowed for hero or major CTA panels.
- Decoration: no abstract blobs, decorative orbs, empty illustrations, or visual noise.

## Typography

- Large headings are allowed only in true hero or major section titles.
- Inner panels, cards, controls, and forms use tighter, smaller typography.
- Letter spacing stays normal.
- Text must not overflow, overlap, or force awkward wrapping.
- Headings should be concrete, not emotional slogans.

Good:
- `Когда нужен курс`
- `5 модулей`
- `Оставить заявку`
- `Есть помещение и площадь?`

Avoid:
- repeated headings with the same meaning;
- generic marketing phrases;
- long explanations before the user sees an action.

## Page Structure

Each page should work as a decision route.

Recommended order:

1. Hero: what this page is and when it is useful.
2. Fit block: who should use it and who should go elsewhere.
3. Main working block: calculator, catalog grid, course program, form, or object flow.
4. Conditions or format: price, access, scope, delivery, constraints.
5. Final action: one clear next step.

Do not add sections that repeat the same decision already made above.

## Copywriting

Tone: direct, practical, calm.

The text should explain:

- what this is;
- who it is for;
- when not to use it;
- what action to take next.

Keep sentences short. Prefer concrete nouns and verbs.

Good:
- `База перед расчётом, закупкой и запуском.`
- `Идите в калькулятор или консультацию.`
- `Напишите вводные и контакт.`
- `Если нужен расчёт, перенаправлю.`

Avoid:
- `уникальная возможность`;
- `лучшее решение`;
- `комплексный подход`;
- repeated `понять`, `курс`, `расчёт`, `система` in every block.

## Buttons

Primary button:

- deep green background;
- light text;
- direct action.

Secondary button:

- transparent or light background;
- green text;
- thin green border.

Button labels should be short:

- `Оставить заявку`
- `Открыть калькулятор`
- `Смотреть видео`
- `В каталог`
- `Написать в Telegram`

Avoid several buttons with the same destination or meaning in one block.

## Cards And Panels

Cards are working units, not decoration.

Each card should usually contain:

- short tag or category;
- heading;
- one short explanation;
- optional action only if it is needed.

Cards should not become long articles. If content is detailed, use accordion/details blocks.

## Accordions

Use accordions when a block needs detail but the first screen should stay compact.

Good use cases:

- course modules;
- FAQ only when it does not repeat existing sections;
- product technical details;
- calculator assumptions;
- category explanations.

Visible summary should answer the basic question. Expanded content should add real detail, not repeat the summary.

## Images

Images must show the actual subject:

- farm;
- equipment;
- plant;
- course cover;
- process;
- product;
- real context.

Do not use images only as atmosphere. If a course has a recognizable cover, use it as a product signal. Do not duplicate the same photo as both hero background and card image unless the composition specifically needs it.

## Header And Footer

Header and footer should stay consistent across pages.

Header:

- compact;
- green;
- clear navigation;
- one main contact/action.

Footer:

- structured grid;
- routes, documents, contacts;
- no unstyled plain text;
- no excessive copy.

## Page-Specific Rules

### Home

The home page is the main route selector. It should quickly explain the system and point to calculator, catalog, course, consultation, and objects.

### Calculator

The calculator is a working tool. It should prioritize inputs, results, assumptions, and next action. Avoid marketing sections around it.

### Catalog

The catalog is for selection and comparison. It should be scannable, dense enough, and practical. Product cards should focus on role, fit, price, availability, and next step.

### Klubhack

The course page should not read like a motivational sales page. It should answer:

- when the course is useful;
- when a calculator or consultation is better;
- what is inside the modules;
- what the format and price are;
- how to apply.

Use module accordions for detail. Avoid a separate FAQ if it repeats fit, format, or application blocks.

### Consultations

Consultation pages should be even more direct: situation, what will be reviewed, what the user needs to send, result, price/format, request form.

## Final Check Before Shipping

Before considering a page ready, check:

- no repeated section meaning;
- no duplicate CTA labels in adjacent blocks;
- no unstyled footer/header state;
- no horizontal overflow on mobile;
- text fits in buttons and cards;
- every section has a clear job;
- the next action is obvious.
